## 1. UI
### 1.1. 개념
- **사용자 인터페이스 (UI; User Interface)**
	- ==사용자와 시스템(컴퓨터, 기계 등) 간의 상호작용이 원활하게 이루어지도록 도와주는 장치(하드웨어)나 소프트웨어==

- **예시**
	- **하드웨어 인터페이스**: TV 리모컨, 컴퓨터 메인보드의 연결 단자, USB 장치(키보드, 마우스 등), 스마트폰의 터치스크린 등
	- **소프트웨어 인터페이스**: 컴퓨터 프로그램 화면에 있는 메뉴, 도구 모음 등

### 1.2. 변화 과정
- **초기**: 단순한 사용자와 컴퓨터 간의 상호작용에만 국한되었습니다.
- **중기**: 사용자가 수행할 작업을 구체화하는 **'기능'** 위주로 발전했습니다.
- **최근**: 정보의 내용을 더 잘 전달하기 위한 **'표현 방법(디자인 등)'** 위주로 변경되었습니다.

### 1.3. 주요 분야
1. **제어 (Control)**: 정보 제공과 전달을 위한 물리적인 제어에 관한 분야
2. **구성 (Composition)**: 콘텐츠의 상세적인 표현과 전체적인 구성에 관한 분야
3. **기능 (Function)**: 모든 사용자가 편리하고 간편하게 사용할 수 있도록 하는 기능에 관한 분야

### 1.4. 특징
> UI의 특징은 대부분 **긍정적이고 사용자를 배려하는 당연한 내용**

1. **사용자 만족도 직결 & 잦은 변경**
	- 사용자의 만족도에 가장 큰 영향을 미치는 중요한 요소입니다.
	- 소프트웨어 영역 중에서 **변경이 가장 많이 발생하는 부분**입니다.

2. **편의성과 효율성 증대**
	- 편리성과 가독성을 높여 작업 시간을 단축시키고 업무 이해도를 높입니다.
	- 사용자가 **최소한의 노력**으로 원하는 결과를 얻을 수 있게 해줍니다.

3. **사용자 중심의 설계**
	- 철저하게 **사용자 중심**으로 설계되어 사용자와 기기 간의 상호작용이 원활하도록 해야 합니다.

4. **오류 감소 및 구체적 안내**
	- 작업 수행 결과의 **오류를 줄여줍니다.**
	- 사용자가 막연하게 느끼는 작업 기능에 대해 **구체적인 방법**을 제시해 주어야 합니다.

5. **매개 역할 수행**
	- 정보 제공자와 공급자(사용자) 간의 **매개(연결) 역할**을 수행합니다.

6. **소프트웨어 아키텍처 숙지 (★중요)**
	- 건물을 지을 때 설계도가 필요하듯,
	- UI를 설계하기 위해서는 소프트웨어의 기본 틀인 **소프트웨어 아키텍처를 반드시 숙지**하고 있어야 한다.

### 1.5. 기본 원칙
1. **직관성** (Intuitiveness)
	- **의미**: 누구나 ==쉽게 이해==하고 사용할 수 있어야 합니다.
	- **강사님 예시**: 명령어를 외워야 했던 과거의 DOS(도스)와 달리, 현재의 윈도우(Windows)나 스마트폰은 따로 학원을 다니며 배우지 않아도 누구나 직관적으로 쉽게 사용할 수 있는 것이 대표적인 예입니다.

2. **유효성** (Effectiveness)
	- **의미**: 사용자의 ==목적을 정확하고 완벽하게 달성==해야 합니다.
	- (사용자가 해당 기기나 프로그램을 통해 하고자 하는 바를 완벽히 해낼 수 있어야 함을 의미합니다.)

3. **학습성** (Learnability)
	- **의미**: 누구나 ==쉽게 배우고== 익힐 수 있어야 합니다.

4. **유연성** (Flexibility)
	- **의미**: 사용자의 ==요구사항을 최대한 수용==하고 실수를 최소화해야 합니다.
	- **강사님 예시**: 스마트폰에서 앱 아이콘을 누를 때, 100% 정확한 픽셀 위치를 누르지 않고 근처만 대충 터치해도 앱이 실행되도록 만들어진 것은 사용자의 실수를 시스템이 보완해 주는 '유연성'의 좋은 예입니다.

### 1.6. 설계 지침
1. **사용자 중심**
	- **내용**: 사용자가 쉽게 이해하고 편리하게 사용할 수 있는 환경을 제공해야 합니다.
	- **특징**: 실사용자에 대한 이해가 바탕이 되어야 합니다.

2. **일관성**
	- **내용**: 버튼이나 조작 방법 등을 일관성 있게 제공하여 쉽게 기억하고 습득할 수 있게 해야 합니다.
	- **예시**: 윈도우에서 마우스 왼쪽 한 번 클릭(선택), 더블 클릭(실행), 오른쪽 클릭(단축 메뉴) 등의 규칙이 모든 프로그램에서 동일하게 적용되는 것.

3. **단순성**
	- **내용**: 조작 방법을 단순화시켜 사용자의 인지적 부담을 감소시켜야 합니다.
	- **예시**: 명령어를 다 외워야 했던 까만 화면의 도스(CLI) 시절과 달리, 현재의 윈도우(GUI) 환경은 단순해져서 초보자도 쉽게 쓸 수 있습니다.

4. **결과 예측 가능**
	- **내용**: 작동시킬 기능만 보고도 그 결과를 미리 예측할 수 있게 설계해야 합니다.
	- **예시**: 윈도우 창 우측 상단의 'X' 버튼을 누르면 창이 닫힌다는 것을 사용자가 누르기 전부터 미리 알 수 있는 것.

5. **가시성**
	- **내용**: 메인 화면에 주요 기능을 노출시켜서 최대한 조작이 쉽도록 설계해야 합니다.

6. **표준화**
	- **내용**: 기능 구조와 디자인을 표준화하여, 한 번 학습한 이후에는 쉽게 사용할 수 있도록 설계해야 합니다.
	- **예시**: 한글, 엑셀, 파워포인트 같은 프로그램은 레이아웃이 표준화되어 있어 10년 전 버전을 쓰던 사람도 최신 버전을 쉽게 사용할 수 있습니다.

7. **접근성**
	- **내용**: 사용자의 연령, 성별, 인종 등 다양한 계층의 사람들이 모두 무리 없이 사용할 수 있도록 설계해야 합니다.

8. **명확성**
	- **내용**: 사용자가 개념적으로 쉽게 인지할 수 있도록 명확하게 설계해야 합니다.

9. **오류 발생 해결**
	- **내용**: 오류가 발생했을 때 사용자가 이를 쉽게 인지하고 대처(해결)할 수 있도록 설계해야 합니다.

## 2. UX
### 2.1. 개념
- **사용자 경험 (UX; User Experience)**
	- 사용자가 시스템이나 서비스를 이용하면서 느끼고 생각하게 되는 ==총체적인 경험==을 의미
	- 단순히 기능이나 절차가 편리하다는 만족감을 넘어, 사용자가 직접 참여하고 상호 교감하며 얻는 가치 있는 경험

- **목적**
	- 기술을 효율성 측면에서만 보는 것이 아니라, **사용자의 삶의 질을 향상**시키는 방향으로 접근하는 새로운 개념
	- 예시: 과거에는 직접 길거리에 나가 손을 흔들어 택시를 잡아야 했지만, 지금은 앱(어플)을 통해 원하는 장소로 택시를 바로 부를 수 있게 된 편리한 경험

### 2.2. UI와 UX의 차이
- **UI (사용자 인터페이스)**
	- 사용성, 접근성, 편의성 등 기기나 소프트웨어 자체의 **기능적인 조작성**을 중시

- **UX (사용자 경험)**
	- 이러한 UI를 통해 사용자가 궁극적으로 느끼는 **만족감이나 감정**을 중시
	- (UI를 포괄하는 더 넓은 개념)

### 2.3. 특징
1. **주관성** (Subjectivity): 사람마다 개인적, 신체적, 인지적 특성이 다르기 때문에 경험하는 방식과 느낌도 **주관적**입니다.
2. **정황성** (Contextuality): 해당 경험이 일어나는 특정 **상황이나 주변 환경, 시간** 등에 큰 영향을 받습니다.
3. **총체성** (Holistic): 단편적인 느낌이 아니라, 개인이 느끼는 **총체적(전체적)인 심리적, 감성적 결과물**입니다.
