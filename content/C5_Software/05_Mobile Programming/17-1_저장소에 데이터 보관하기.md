| :-------------------------------------------: | :---------: |
|          `execSQL(sql, args): Unit`           |   원시 C-UD   |
|         `rawQuery(sql, args): Cursor`         |    원시 R     |
| `insert()`, `query()`, `update()`, `delete()` |   고급 CRUD   |
|                 `onCreate()`                  |    최초 1회    |
|                 `onUpgrade()`                 |  DB 버전 변경   |

|              `writableDatabase`               | 쓰기 모드 DB 접근 |

## 1. 데이터베이스에 파일 저장 (SQLite)
### 1.1. 안드로이드 데이터베이스 개요
- 안드로이드는 오픈소스 **SQLite**를 DBMS로 탑재
- 모바일용 **경량화 데이터베이스**
- 앱의 저장소에 **파일 형태**로 저장 → 외부 앱 접근 불가
- 데이터의 CRUD 작업: **Create(insert), Read(select), Update, Delete**

### 1.2. SQLiteDatabase 객체 생성
```kotlin
val db = openOrCreateDatabase("testdb", Context.MODE_PRIVATE, null)
```

|  인자  |                   설명                   |
| :--: | :------------------------------------: |
| 첫 번째 |           DB 이름 (없으면 새로 생성)            |
| 두 번째 | `Context.MODE_PRIVATE` → 현재 앱에서만 접근 가능 |
| 세 번째 |        커서 팩토리 (null = 기본 커서 사용)        |

> **커서(Cursor)**: 쿼리 결과를 저장하는 객체로, 데이터베이스 조회 시 결과값을 담음

### 1.3. SQL 실행 함수
|              함수               |         용도         |
| :---------------------------: | :----------------: |
|  `execSQL(sql, args): Unit`   | 테이블 생성, 삽입, 삭제, 수정 |
| `rawQuery(sql, args): Cursor` |       데이터 조회       |

```kotlin
// 테이블 생성
db.execSQL("
	create table USER_TB(
		_id INTEGER primary key autoincrement,
		name TEXT not null,
		phone TEXT
	)
")

// 데이터 삽입
db.execSQL(
	"insert into USER_TB(name, phone) values (?,?)",
	arrayOf<String>("kkang","0101111")
)

// 데이터 조회
val cursor = db.rawQuery("select * from USER_TB", null)
```

### 1.4. Cursor 사용법
#### (1) 행(Row) 이동 함수
|         함수          |           설명           |
| :-----------------: | :--------------------: |
|   `moveToFirst()`   |       첫 번째 행 선택        |
|   `moveToLast()`    |        마지막 행 선택        |
|   `moveToNext()`    | 다음 행 선택 (없으면 false 반환) |
| `moveToPrevious()`  |        이전 행 선택         |
| `moveToPosition(n)` |      n번째 위치의 행 선택      |

- **커서 초기 위치**
	- Before First (인덱스 -1; 데이터 시작 바로 직전)

#### (2) 열(Column) 데이터 가져오기
```kotlin
while (cursor.moveToNext()) {
	val name = cursor.getString(0)	// 첫 번째 열
	val phone = cursor.getString(1)	// 두 번째 열
}
```

|         함수         | 타입  |
| :----------------: | :-: |
| `getString(index)` | 문자열 |
|  `getInt(index)`   | 정수  |
| `getDouble(index)` | 실수  |

### 1.5. 데이터 다루는 함수 (CRUD)
- 원시 SQL문 대신 안드로이드에서 제공하는 메서드를 사용할 수도 있다.

#### (1) INSERT
- `insert()`: 테이블에 데이터 추가
	- (ContentValues 객체에 컬럼-값 쌍으로 저장하여 전달)`
```kotlin
val values = ContentValues()
values.put("name", "홍길동")
values.put("phone", "010-1234-5678")
val newRowId = db.insert("USER_TB", null, values) // 값이 없는 컬럼에는 null을 저장
// 성공 시 고유 ID 반환, 실패 시 -1 반환
```

#### (2) UPDATE
- `update()`: 조건에 맞는 데이터 수정
```kotlin
val values = ContentValues()
values.put("phone", "010-9999-8888")
val updatedCount = db.update("USER_TB", values, "name = ?", arrayOf("홍길동"))
// 수정된 ROW 개수 반환
```

#### (3) DELETE
- `delete()`: 조건에 맞는 데이터 삭제
```kotlin
val deletedCount = db.delete("USER_TB", "name = ? AND phone = ?", arrayOf("홍길동", "010-1234-5678"))
// 삭제된 ROW 개수 반환
```

#### (4) SELECT
- `query()`: 구조화된 SELECT 쿼리 실행`
```kotlin
val cursor = db.query(
    "USER_TB",              // table
    arrayOf("name","phone"), // columns
    "phone=?",              // selection (where절)
    arrayOf("0101112"),     // selectionArgs (?에 삽입)
    null,                   // groupBy
    null,                   // having
    null                    // orderBy
)
```

|      매개변수       |       의미       |
| :-------------: | :------------: |
|     `table`     |    조회할 테이블명    |
|    `columns`    |  가져올 열 이름 배열   |
|   `selection`   |   WHERE 조건식    |
| `selectionArgs` |  ?에 들어갈 값 배열   |
|    `groupBy`    |   GROUP BY 절   |
|    `having`     |   HAVING 조건    |
|    `orderBy`    | ORDER BY 정렬 기준 |

### 1.6. SQLiteOpenHelper
- `SQLiteOpenHelper`
	- 테이블 **생성, 변경, 제거**를 관리하는 추상 클래스
	- 추상 클래스이므로 반드시 상속받아 하위 클래스 작성 필요

|      메서드      |    호출 시점     |     용도     |
| :-----------: | :----------: | :--------: |
| `onCreate()`  | 앱 설치 후 최초 1회 |   테이블 생성   |
| `onUpgrade()` | DB 버전 변경 시마다 | 테이블 스키마 변경 |

```kotlin
class DBHelper(context: Context) : SQLiteOpenHelper(context, "testdb", null, 1) {
    override fun onCreate(db: SQLiteDatabase?) {
        db!!.execSQL("CREATE TABLE groupTBL (gName CHAR(20) PRIMARY KEY, gNumber INTEGER);")
    }
    override fun onUpgrade(db: SQLiteDatabase?, oldVersion: Int, newVersion: Int) {
        db!!.execSQL("DROP TABLE IF EXISTS groupTBL")
        onCreate(db)
    }
}
```

- **`onCreate(db)`**
	- 앱 설치 후 DB가 처음 생성될 때 1회 호출됨
	- 주로 **테이블 생성(`CREATE TABLE`)** 코드를 작성

- **`onUpgrade(db, old, new)`**
	- DB 버전 번호가 변경될 때 호출됨
	- 주로 **기존 테이블 삭제(`DROP`) 후 재생성** 등 스키마 변경 코드를 작성

```kotlin
// 쓰기 모드로 DB 객체 생성
val db: SQLiteDatabase = DBHelper(this).writableDatabase

// 읽기 모드로 DB 객체 생성
val db: SQLiteDatabase = DBHelper(this).readableDatabase
```

## 3. 파일 저장 기본 개념
- 안드로이드 앱에서 파일을 다룰 때는
	- 자바 프로그램과 동일하게 `java.io.*` 패키지를 사용하여 파일을 읽거나 쓴다.

- **주요 클래스**는 다음과 같다.
	- **File 클래스**: 파일 및 디렉터리를 다루는 클래스
	- **FileReader / FileWriter**: 파일에서 **문자열 스트림**으로 데이터를 읽거나 쓰는 클래스
	- **FileInputStream / FileOutputStream**: 파일에서 **바이트 스트림**으로 데이터를 읽거나 쓰는 클래스

- 앱별 저장소(`/data/data/앱이름`)에 저장된 데이터는
	- 외부에서 접근할 수 없다는 특징이 있다.

|  구분   |             내장 메모리             |                  외장 - 앱별 저장소                  |         외장 - 공용 저장소         |
| :---: | :----------------------------: | :-------------------------------------------: | :-------------------------: |
| 저장 위치 |       `/data/data/패키지명`        | `/storage/emulated/0/Android/data/패키지명/files` |          시스템 지정 폴더          |
| 접근 방법 | `filesDir`, `openFileOutput()` |            `getExternalFilesDir()`            |           시스템 API           |
|  특징   |     앱 전용, 외부 접근 불가, 용량 작음      |                 앱 삭제 시 함께 삭제                  | 모든 앱 공유, 앱 삭제 후에도 유지, 권한 필요 |

## 4. 내장 메모리의 파일 이용하기
- 안드로이드 기기에 앱을 설치하면
	- 앱의 패키지명으로 디렉터리가 생성되며, 이 디렉터리가 앱의 내장 메모리 공간이 된다.
	- 파일을 내장 메모리에 저장하려면 `java.io`의 `File` 클래스를 이용한다.
	- 내장 메모리 공간은 용량이 작기 때문에 크기가 큰 데이터는 외장 메모리에 저장해야 한다.

### 방법 1: File 클래스 직접 사용
```kotlin
// 파일 객체 생성 후 데이터 쓰기
val file = File(filesDir, "test.txt") // 경로, 파일명
val writeStream: OutputStreamWriter = file.writer()
writeStream.write("hello world")
writeStream.flush() // 파일 저장

// 파일의 데이터 읽기
val readStream: BufferedReader = file.reader().buffered()
readStream.forEachLine {
    Log.d("tukorea", "$it")
}
```

### 방법 2: Context 객체의 함수 사용
- `openFileOutput("파일명", 모드)`, `openFileInput("파일명")` 함수를 통해 스트림을 열어 읽고 쓴다.
```kotlin
openFileOutput("test.txt", Context.MODE_PRIVATE).use {
    it.write("hello world!!".toByteArray())
}

openFileInput("test.txt").bufferedReader().forEachLine {
    Log.d("tukorea", "$it")
}
```

- 주요 함수 설명:
	- `use { }`: 자원 자동 해제 블록으로 메모리 누수를 차단
	- `bufferedReader()`: 데이터를 문자 단위로 버퍼에 읽어옴
	- `forEachLine { }`: 파일을 처음부터 끝까지 한 줄씩 읽고, 마지막에 자동으로 닫음

## 5. 외장 메모리의 파일 이용하기
- 기기마다 외장 메모리의 탑재 여부가 다르기 때문에
	- `Environment.getExternalStorageState()` 함수로
	- 외장 메모리의 사용 가능 여부를 확인한 후 사용해야 한다.

```kotlin
// 외장 메모리 사용 가능 여부 판단
if (Environment.getExternalStorageState() == Environment.MEDIA_MOUNTED) {
    Log.d("tukorea", "ExternalStorageState MOUNTED")
} else {
    Log.d("tukorea", "ExternalStorageState UNMOUNTED")
}
```

- 외장 메모리 공간은 **앱별 저장소**와 **공용 저장소**로 구분된다.

### 5.1. 앱별 저장소 이용
- 앱별 저장소는
	- 개별 앱에 할당된 공간이며,
	- 앱별 저장소의 파일을 외부 앱에서 접근하게 하려면 파일 프로바이더로 공개해야 한다.
	- 외장 메모리의 앱별 저장소 위치는 `getExternalFilesDir()`로 확인 가능하며,
	- `null`을 넘겨줄 경우 앱의 기본 디렉토리를 의미한다.

```kotlin
// 앱별 저장소에 접근
val file: File? = getExternalFilesDir(null)
Log.d("tukorea", "${file?.absolutePath}")
// /storage/emulated/0/Android/data/com.example.file_project/files
```

### 5.2. getExternalFilesDir() 함수의 매개변수
- 매개변수는 파일의 종류를 나타내며, 필요에 따라 `Environment`의 상수를 전달한다.
	- `Environment.DIRECTORY_PICTURES`: 사진 저장 폴더
	- `Environment.DIRECTORY_DOCUMENTS`: 문서 저장 폴더
	- `Environment.DIRECTORY_MUSIC`: 음악 저장 폴더
	- `Environment.DIRECTORY_MOVIES`: 동영상 저장 폴더

```kotlin
// 파일 쓰기
val file: File = File(getExternalFilesDir(null), "test.txt")
val writeStream: OutputStreamWriter = file.writer()
writeStream.write("hello world")
writeStream.flush()

// 파일 읽기
val readStream: BufferedReader = file.reader().buffered()
readStream.forEachLine {
    Log.d("tukorea", "$it")
}
```

### 5.3. 공용 저장소 이용
- 공용 저장소는
	- 모든 앱이 이용할 수 있는 저장소로,
	- 주로 카메라 앱에서 촬영한 사진 파일을 저장하는 데 사용된다.
	- 앱별 저장소의 파일은 앱을 삭제하면 함께 삭제되지만,
	- 공용 저장소의 파일은 삭제되지 않는다는 차이가 있다.

- 공용 저장소는
	- 안드로이드 시스템에서 파일 종류(사진, 음원, 문서 등)에 따라 폴더가 지정되어 있으며,
	- 파일 경로로 직접 접근하지 않고 시스템이 제공하는 API를 이용해야 한다.
	- 파일의 타입에 따라 사용 방법도 다르다.

### 5.4. 공용 저장소 권한 설정 (API Level별 변화)
- API Level에 따라 권한 설정 방식이 다음과 같이 변화했다.
	- **안드로이드 12 (API Level 32) 이전**: `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE` 권한 사용
	- **안드로이드 13 (API Level 33)**: 공용 공간의 파일 타입을 구분해서 이용하므로 미디어 파일도 이미지/비디오에 따라 다르게 권한 설정
	- **안드로이드 14**: 사용자가 앱의 미디어 파일 접근을 다시 선택할 수 있도록 `READ_MEDIA_VISUAL_USER_SELECTED` 권한이 추가됨

```xml
<!-- API Level 32 이전 -->
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"/>
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"/>

<!-- API Level 33 -->
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES"/>
<uses-permission android:name="android.permission.READ_MEDIA_VIDEO"/>

<!-- API Level 34 이후 -->
<uses-permission android:name="android.permission.READ_MEDIA_VISUAL_USER_SELECTED"/>
```

## 6. 실습: 파일 쓰고 읽기
> 내부 저장소(file 디렉터리)에 `file.txt` 파일을 생성한 후,
> 해당 파일에 텍스트를 입력하고 읽어오는 기본 예제이다.

### 6.1. 파일 쓰기
- 문자열을 바이트 배열 형태로 파일에 입력해야 하므로
	- `toByteArray()` 메소드로 변환한 후
	- `write()` 메소드에 전달한다.

```kotlin
binding.btnWrite.setOnClickListener {
    var outFs: FileOutputStream = openFileOutput("file.txt", Context.MODE_PRIVATE)
    var str = "모바일 프로그래밍"
    outFs.write(str.toByteArray()) // 문자열을 바이트 단위로 변환
    outFs.close()
    Toast.makeText(applicationContext, "file.txt가 생성됨", Toast.LENGTH_SHORT).show()
}
```

### 6.2. 파일 읽기
- 파일을 읽어올 수 없는 경우에 앱이 비정상 종료하지 않도록 예외 처리 코드로 작성한다.
- 바이트 배열 타입으로 파일 내부의 문자열을 읽어서 스트링으로 변환하며,
- **UTF-8 포맷의 문자열로 변환해야 한글이 깨지지 않는다**.

```kotlin
binding.btnRead.setOnClickListener {
    try {
        var inFs: FileInputStream = openFileInput("file.txt")
        var txt = ByteArray(30) // 요소가 30개인 바이트형 배열 선언
        inFs.read(txt)
        var str = txt.toString(Charsets.UTF_8)
        Toast.makeText(applicationContext, str, Toast.LENGTH_SHORT).show()
        inFs.close()
    } catch (e: IOException) {
        Toast.makeText(applicationContext, "파일 없음", Toast.LENGTH_SHORT).show()
    }
}
```
