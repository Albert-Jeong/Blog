## 요약
|       알고리즘        |    시간 복잡도     |       비고       |
| :---------------: | :-----------: | :------------: |
| **Counting Sort** |  $O(n + k)$   | 안정, k가 작아야 효율적 |
|  **Radix Sort**   | $O(d(n + k))$ |  d가 상수면 O(n)   |

## 1. 기존 정렬 알고리즘 복습
> 지금까지 배운 정렬 알고리즘들을 정리하면 다음과 같다.

- **Insertion Sort**
	- 코딩이 쉽다.
	- 작은 입력(~50개 미만)이나 거의 정렬된 입력에서 빠르다.
	- 최악/평균/역순 모두 O(n²)

- **Merge Sort**
	- 분할정복 방식: 배열을 절반으로 나누고 재귀적으로 정렬한 뒤 병합
	- 최악 O(n lg n)
	- in-place가 아님

- **Heap Sort**
	- 힙 자료구조(완전 이진 트리, 부모 키 > 자식 키)를 활용
	- 최악 O(n lg n)
	- in-place 정렬

- **Quick Sort**
	- 분할정복 기반
	- 평균 O(n lg n)
	- 최악 O(n²) (정렬된 입력에서 발생)
	- 랜덤화로 개선 가능

### 1.1. 비교 기반 정렬의 하한 (Lower Bound)
- 지금까지의 정렬은 모두 **비교 정렬(comparison sort)**이다.
	- 즉, 두 원소의 쌍별 비교만으로 순서 정보를 얻는다.

- **결정 트리(Decision Tree)** 모델을 통해 다음을 증명할 수 있다.
	- n개 원소를 정렬하는 모든 경우의 수는 n!개이므로, 결정 트리의 잎(leaf)은 최소 n!개 필요
	- 높이 h인 이진 트리의 최대 잎 수는 $2^h$이므로 $n! ≤ 2^h$
	- 양변에 로그를 취하고 스털링 근사 n! > (n/e)ⁿ를 적용하면:
		- $h \geq \lg\left(\frac{n}{e}\right)^n = n\lg n - n\lg e = \Omega(n \lg n)$

- **결론**
	- 모든 비교 정렬은 Ω(n lg n)이며,
	- Heap Sort와 Merge Sort는 점근적으로 최적이다.
	
	- *선형 시간 $O(n)$에 정렬하려면 비교를 사용하지 않아야 한다.*

## 2. 선형 시간 정렬 (Sorting in Linear Time)
- 비교를 전혀 하지 않고 **선형 시간**에 정렬하는 알고리즘

### 2.1. Counting Sort (계수 정렬)
- 단, 입력이 0~k 범위의 정수라는 가정이 필요하다.

- **기본 아이디어**
	- 각 원소 x에 대해 x보다 작거나 같은 원소의 개수를 세어 위치를 결정

- **저장 공간**
	- $A[1..n]$: 입력
	- $B[1..n]$: 정렬 결과
	- $C[0..k]$: 카운팅 배열

- **알고리즘 단계**
	1. $C[i] ← 0$ 으로 초기화
		- $Θ(k)$
	2. $C[A[j]]++$ 로 각 값의 개수 세기
		- $Θ(n)$
	3. $C[i] ← C[i] + C[i-1]$ 누적합 계산
		- $Θ(k)$
	4. A를 뒤에서부터 순회하며 $B[C[A[j]]] ← A[j], C[A[j]]--$
		- $Θ(n)$

- **총 시간 복잡도**
	- $Θ(n + k)$
	- $k = O(n)$이면 $O(n)$

- **특징**
	- 비교 기반이 아니므로 Ω(n lg n) 하한과 모순되지 않음
	- **안정 정렬(stable)**: 같은 값의 상대적 순서가 보존됨

### 2.2. Radix Sort (기수 정렬)
- 여러 자릿수를 가진 숫자나 문자열을 정렬할 때 사용한다.

- **핵심 아이디어**
	- **최하위 자릿수(LSD)부터** 안정 정렬을 적용

```c
RadixSort(A, d) {
	for (i = 1 to d) {
		StableSort(A) on digit i
	}
}
```

- 각 자릿수에 대해 Counting Sort를 안정 정렬로 사용하면
	- 한 패스: $O(n + k)$
	- $d$ 자릿수 전체: $O(d(n + k))$
	- $d$가 상수이고 $k = O(n)$이면 $O(n)$

- 장점
	- 빠르다.
	- 점근적으로 선형이다.
	- 코딩이 단순하다.

## 3. Medians and Order Statistics (순위 통계)
- **i번째 순위 통계량**: n개 원소 중 i번째로 작은 원소
	- 최솟값 = 1번째 순위 통계량
	- 최댓값 = n번째 순위 통계량
	- 중앙값 = n/2번째 순위 통계량 (n이 짝수면 lower/upper median)

- 정렬 후 찾으면 O(n lg n)이지만, **모든 원소를 정렬할 필요는 없다**.

### 3.1. Min/Max 동시에 찾기
- 원소를 쌍으로 묶어 처리하면 **3 비교 / 2 원소** = O(3n/2)로 가능

### 3.2. Randomized Selection
- Quicksort의 partition을 활용하되, **한쪽 부분 배열만** 재귀 탐색
	- 최악: T(n) = T(n-1) + O(n) = O(n²)
	- 최선/평균: T(n) = T(9n/10) + O(n) = **O(n)**
	- 기대 시간: O(n) (지시 확률 변수와 치환법으로 증명)

### 3.3. Worst-Case Linear Time Selection (Median of Medians)
- 이론적 관심의 알고리즘으로 **최악의 경우에도 O(n)** 보장
	1. n개 원소를 5개씩 그룹으로 나눔
	2. 각 그룹의 중앙값을 구함
	3. ⌊n/5⌋개 중앙값들의 중앙값 x를 재귀적으로 찾음
	4. x를 기준으로 partition (rank k 결정)
	5. i = k면 반환, i < k면 왼쪽 재귀, i > k면 오른쪽 재귀

- **핵심 분석**
	- 좋은 피벗 x보다 큰(작은) 원소가 최소 3n/10 - 6개 존재하므로, 재귀 호출은 최대 7n/10 + 6개 원소에 대해서만 발생

- **점화식**
	- $T(n) ≤ T(⌈n/5⌉) + T(7n/10 + 6) + O(n)$
	- → $T(n) = O(n)$

- 치환법으로 증명
	- 1/5 + 7/10 = 9/10 < 1 이라는 점이 핵심이며,
	- 이 때문에 그룹 크기를 5로 잡는다.
