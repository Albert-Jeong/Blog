## 2. 클래스 상속과 객체
### 2.1. 자바의 상속 선언
```java
public class Person {
	// ...
}

public class Student extends Person {
	// Person을 상속받는 클래스 Student 선언
}

public class StudentWorker extends Student {
	// Student를 상속받는 StudentWorker 선언
} 
```
- `extends` 키워드 사용 (슈퍼 클래스를 확장한다는 개념)

### 2.2. 자바 상속의 특징
- 클래스의 다중 상속 지원하지 않음
- 상속 횟수 무제한
- 모든 클래스는 자바 컴파일러에 의해 자동으로 java.lang.Object클래스를 상속받음 (최상위 조상 클래스)

## 4. 상속과 생성자
### 4.1. 생성자 호출 및 실행
- new에 의해 서브 클래스 객체 생성
	- → 서브 클래스 생성자 호출
	- → 슈퍼 클래스 생성자 호출
	- → **슈퍼 클래스 생성자 실행**
	- → **서브 클래스 생성자 실행**

### 4.2. 서브 클래스에서 슈퍼 클래스 생성자 선택
- **서브 클래스 생성자 작성 시**
	- 슈퍼 클래스 생성자를 `super(params);`로 하나 선택한다. (명시적 선택)
		- 명시적 선택의 경우 반드시 서브 클래스 생성자 코드의 제일 첫 라인에 와야 한다.
	- 선택하지 않으면, 컴파일러가 자동으로 슈퍼 클래스의 기본 생성자를 선택한다. (묵시적 선택)

## 5. 업캐스팅
### 5.1. 업캐스팅
- 서브 클래스의 객체
	- 슈퍼 클래스의 멤버를 모두 가지고 있다.
	- 슈퍼 클래스의 객체로 취급할 수 있다.

- **업캐스팅**(upcasting)
	- 서브 클래스 객체를 슈퍼 클래스 타입으로 타입 변환
	- 업캐스팅된 레퍼런스는 객체 내에 슈퍼 클래스의 멤버만 접근 가능

### 5.2. 다운캐스팅
-  **다운캐스팅**(downcasting)
	- *업캐스팅의 다운캐스팅*
	- 슈퍼 클래스 객체를 서브 클래스 타입으로 변환
	- 개발자의 명시적 타입 변환 필요

### 5.3. instanceof 연산자
- **instanceof 연산자**
	- 슈퍼 클래스는 여러 서브 클래스에 상속되기 때문에, 업캐스팅된 레퍼런스로 **객체의 타입 판단** 어려움
	- 레퍼런스가 가리키는 객체의 타입 식별을 위해 사용
	- 사용법
		- `객체레퍼런스 instanceof 클래스타입`
		- 연산의 결과 : true/false의 불린 값

## 6. 메서드 오버라이딩
- *Java에서 메서드 호출이 기본적으로 가상(virtual) 메서드 호출로 동작한다.*

- **오버라이딩**(overriding)
	- 슈퍼 클래스에 선언된 메서드를, 각 서브 클래스들이 자신만의 내용으로 새로 구현하는 기능
	- 상속을 통해 '하나의 인터페이스(같은 이름)에 서로 다른 내용 구현'이라는 객체 지향의 **다형성 실현**

- **메서드 오버라이딩**(method overriding)
	- 슈퍼 클래스의 메서드를 서브 클래스에서 재정의
	- 슈퍼 클래스 메서드의 이름, 매개변수 타입 및 개수, 리턴 타입 등 모든 것 동일하게 작성

- 메서드 오버라이당의 **동적 바인딩**(dynamic binding)
	- 런 타임 중에 실제 객체의 타입에 따라 호출할 메서드가 결정
	- **서브 클래스에 오버라이딩된 메서드가 무조건 실행**

### 6.1. 슈퍼 클래스 레퍼런스(super.)
```java
class Point {
	private int x, y; // 한 점을 구성하는 x, y 좌표
	
	public Point() {
		this.x = this.y = 0;
	}
	public Point(int x, int y) {
		this.x = x; this.y = y;
	}
	public void showPoint() { // 점의 좌표 출력
		System.out.println("(" + x + "," + y + ")");
	}
}
class ColorPoint extends Point {
	private String color; // 점의 색
	
	public ColorPoint(int x, int y, String color) {
		super(x, y); // Point의 생성자 Point(x, y) 호출
		this.color = color;
	}
	public void showColorPoint() { // 컬러 점의 좌표 출력
		System.out.print(color);
		showPoint(); // Point 클래스의 showPoint() 호출
	}
}
public class SuperEx {
	public static void main(String[] args) {
		ColorPoint cp = new ColorPoint(5, 6, "blue");
		cp.showColorPoint();
	}
}
```
- super는 슈퍼 클래스의 멤버를 접근할 때 사용되는 레퍼런스
- 서브 클래스에서만 사용
- 슈퍼 클래스의 메서드 호출
- 컴파일러는 super의 접근을 정적 바인딩으로 처리

### 6.2. 오버로딩 vs. 오버라이딩
- **메서드 오버로딩**
	- 중복정의
	- **정적 바인딩**을 통해 컴파일 타임 다형성 실현
	- 같은 클래스 내 또는 상속 관계

- **메서드 오버라이딩**
	- 재정의
	- **동적 바인딩**을 통해 런 타임 다형성 실현
	- 상속 관계

## 7. 추상 클래스
### 7.1. Concept
- **추상 메서드**(abstract method)
	- `abstract` 선언 O + 구현 X
		- 서브 클래스에서 오버라이딩하여 구현해야 한다.

- **추상 클래스**(abstract class)
	- `abstract` 선언 O
		- 1. 추상 메서드를 하나라도 가진 클래스는 반드시 추상 클래스로 선언한다.
		- 2. 추상 메서드가 없더라도 추상 클래스로 선언할 수 있다.
	- 추상 클래스는 객체를 생성할 수 없다.

### 7.2. Etc.
- **추상 클래스의 상속**
	- 1. **단순 상속**
		- 추상 메서드 구현 X (`abstract` to `abstract`)
	- 2. **구현 상속**
		- 추상 메서드 구현 O (`abstract` to `@Override`)

- **추상 클래스의 용도**
	- 1. **설계와 구현 분리**
		- 슈퍼 클래스에서는 개념 **정의**
		- 각 서브 클래스에서 구체적 행위 **구현**
	- 2. 계층적 상속 관계를 갖는 클래스 구조를 만들 때

## 8. 인터페이스
- **인터페이스**
	- `interface` 선언
	- 클래스가 구현해야 할 메서드들이 선언되는 추상형
	
	- 인터페이스의 객체 생성 불가
	- 인터페이스 타입의 레퍼런스 변수 선언 가능

### 8.1. 인터페이스 구성
- 상수
	- public static final 생략 가능
	- 필드(멤버 변수)는 선언 불가

- `static` 메서드
	- public, private 모두 지정 가능 (생략하면 public)

- `abstract` 메서드
	- public abstract 생략 가능

- default 메서드
	- 인터페이스에 코드가 작성된 메서드
	- public 생략 가능

- `private` 메서드
	- 인터페이스 내에 메서드 코드가 작성되어야 함
	- 인터페이스 내에 있는 다른 메서드에 의해서만 호출 가능

### 8.2. 인터페이스 구현
- `implements` 키워드
- 인터페이스를 상속받는 클래스는 인터페이스의 모든 추상 메서드 반드시 구현

- **다중 인터페이스 구현**
	- 클래스는 하나 이상의 인터페이스를 구현할 수 있다.

```java
interface PhoneInterface { // 인터페이스 선언
	final int TIMEOUT = 10000; // 상수 필드 선언
	void sendCall(); // 추상 메소드
	void receiveCall(); // 추상 메소드
	default void printLogo() { // default 메소드
		System.out.println("** Phone **");
	}
}
class SamsungPhone implements PhoneInterface { // 인터페이스 구현
	// PhoneInterface의 모든 메소드 구현
	@Override
	public void sendCall() {
		System.out.println("띠리리리링");
	}
	@Override
	public void receiveCall() {
		System.out.println("전화가 왔습니다.");
	}
	// 메소드 추가 작성
	public void flash() {
		System.out.println("전화기에 불이 켜졌습니다.");
	}
}
public class InterfaceEx {
	public static void main(String[] args) {
		SamsungPhone phone = new SamsungPhone();
		phone.printLogo();
		phone.sendCall();
		phone.receiveCall();
		phone.flash();
	}
}
```

### 8.3. 인터페이스 상속
- 다른 인터페이스 상속 가능
- 인터페이스의 다중 상속 가능

- 인터페이스가 다른 인터페이스 상속
	- `extends` 키워드 이용
	- 다중 인터페이스 상속

```java	
interface PhoneInterface { // 인터페이스 선언
	final int TIMEOUT = 10000; // 상수 필드 선언
	void sendCall(); // 추상 메소드
	void receiveCall(); // 추상 메소드
	default void printLogo() { // default 메소드
		System.out.println("** Phone **");
	}
}
interface MobilePhoneInterface extends PhoneInterface {
	void sendSMS();
	void receiveSMS();
}
interface MP3Interface { // 인터페이스 선언
	public void play();
	public void stop();
}
class PDA { // 클래스 작성
	public int calculate(int x, int y) { return x + y; }
}
// SmartPhone 클래스는 PDA를 상속받고,
// MobilePhoneInterface와 MP3Interface 인터페이스에 선언된 추상 메소드를 모두 구현한다.
class SmartPhone extends PDA implements MobilePhoneInterface, MP3Interface {
	// MobilePhoneInterface의 추상 메소드 구현
	@Override
	public void sendCall() { System.out.println("따르릉따르릉~~"); }
	@Override
	public void receiveCall() { System.out.println("전화 왔어요."); }
}
```

### 8.4. 인터페이스 목적
- 인터페이스는 스펙을 주어 클래스들이 그 기능을 서로 다르게 구현할 수 있도록 하는 클래스의 규격 선언이며, 클래스의 다형성을 실현하는 도구이다.

### 8.5. ==인터페이스 vs. 추상 클래스==
- 유사점
	- 객체를 생성할 수 없고, 상속을 위한 슈퍼 클래스로만 사용
	- 클래스의 다형성을 실현하기 위한 목적

- *차이점*
	- 인터페이스는 무엇을 할 수 있는가(규약)를 정의한다.
	- 추상 클래스는 어떻게 공통적으로 할 것인가(기본 구현)을 정의한다.
