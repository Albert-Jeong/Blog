## 1. Database System
### 1.1. 개요
- 데이터베이스 시스템(DBS, database system)
	- 데이터베이스와 DBMS를 이용해 조직에 필요한 정보를 제공해 주는 전체 시스템
	- 데이터베이스 + DBMS + 데이터 모델 + 응용 프로그램 + 컴퓨터

- 데이터베이스 시스템의 구성
	- ① 하드웨어
	- ② 데이터베이스
	- ③ DBMS
	- ④ 사용자(응용 프로그램)

### 1.2. 아키텍처
- ① DBA의 DDL
	- DDL 컴파일러 → 시스템 카탈로그
	- → 런타임 DB 관리기 (저장된 DB, 트랜잭션 관리기)

- ② 프로그래머/최종 사용자의 기작성 트랜잭션/DML
	- 질의 처리기
	- → 런타임 DB 관리기 (저장된 DB, 트랜잭션 관리기)

## 2. Database
### 2.1. 개요
- 데이터: 현실 세계에서 단순히 관찰하거나 측정하여 수집한 사실이나 실제 값
- 정보: 데이터를 의사 결정에 활용할 수 있도록 처리한 결과물

- 데이터베이스(database)
	- 어떤 조직체의 여러 사용자가 공유하여 사용하는 연관된 운영 데이터(operational data)들을 구조적으로 통합 저장한 데이터이다.

- 데이터베이스의 특징
	- 실시간 접근성(real time accessibility)
	- 계속적인 변화(continuous change)
	- 동시 공유(concurrent sharing)
	- 내용 기반 참조(reference by content)

### 2.2. 스키마/상태
- ① 데이터베이스 스키마(schema) 또는 내포(intension)
	- 데이터베이스에 저장되는 데이터 구조와 제약조건을 정의
	- 자주 변경되지 않으며, 데이터베이스의 모든 가능한 상태를 미리 정의한다.

- ② 데이터베이스 상태(state) 또는 외연(extension)
	- 특정 시점의 데이터베이스의 내용
	- 시간이 지남에 따라 계속해서 바뀐다.

### 2.3. 시스템 카탈로그
- 시스템 카탈로그(system catalog)
	- 저장된 데이터베이스의 스키마 정보를 유지한다.
	- 데이터베이스는 시스템 카탈로그(또는 데이터 사전)와 저장된 데이터베이스로 구성된다.

### 2.4. ANSI/SPARC 아키텍처
- *cf. 의미*
	- 미국 국가 표준 협회(American National Standards Institute)
	- 표준 기획 및 요구사항 위원회(Standards Planning And Requirements Committee)

- DBMS는 세 스키마 간의 사상(mapping)을 책임진다.

- 목적
	- 데이터 독립성(data independence)
		- 상위 스키마 정의에 영향을 주지 않으면서 해당 스키마 정의를 변경할 수 있음

#### (1) 외부 단계(external level) 또는 뷰 단계
- 외부 스키마(서브 스키마)
	- 각 사용자가 어떻게 데이터베이스를 보는가를 기술한다. (개념 단계를 보는 관점)
	- 동일한 개념 단계로부터 다수의 서로 다른 뷰가 제공될 수 있다.

#### (2) 개념 단계(conceptual level) 또는 논리적 단계
- 개념 스키마(논리 스키마)
	- 데이터베이스의 논리적 구조(어떤 데이터가 저장되어 있으며, 어떤 관계가 존재하고, 어떤 무결성 제약조건이 명시되어 있는가)를 기술한다.
	- 데이터베이스마다 오직 한 개의 개념 단계/개념 스키마가 존재한다.

- 논리적 데이터 독립성: 서브 스키마에 영향을 주지 않고 논리 스키마를 수정할 수 있음

#### (3) 내부 단계(internal level) 또는 물리적 단계
- 내부 스키마(물리 스키마)
	- 데이터베이스에 어떤 데이터가 어떻게 저장되어 있는가(인덱스, 해싱 등과 같은 접근 경로, 데이터 압축 등)를 기술한다.
	- 이 단계에서는 효율성을 가장 중요하게 고려하며, 효율적인 데이터베이스를 제공하기 위한 저장 구조가 선택된다.

- 물리적 데이터 독립성: 논리 스키마에 영향을 주지 않고 물리 스키마를 수정할 수 있음

## 3. DBMS
### 3.1. 개요
- 데이터베이스 관리 시스템(DBMS, database management system)
	- 파일 시스템의 문제(데이터 중복성, 데이터 종속성 등)를 해결하기 위해 제시된 소프트웨어 패키지

- DBMS의 기능
	- ① 정의 기능: 데이터베이스의 스키마(구조) 정의
	- ② 조작 기능: 데이터의 연산 (CRUD: Create, Read, Update, Delete)
	- ③ 제어 기능: 데이터의 일관성·독립성·무결성과 동시성 제어, 보안, 회복

### 3.2. 발전 과정
- 데이터 모델
	- 데이터베이스의 구조를 기술하는 데 사용되는 개념들의 집합인 ‘구조’
	- 이 ‘구조’ 위에서 동작하는 연산자들, 무결성 제약조건들
	
	- 계층 데이터 모델(hierarchical): 트리 구조로 데이터 표현
	- 네트워크 데이터 모델(network): 그래프 구조로 데이터 표현
	- 관계 데이터 모델(relational): 2차원 테이블(릴레이션) 구조로 데이터 표현

- 발전 과정
	- 파일 시스템
	- → 계층 데이터 모델 → 네트워크 데이터 모델 → 관계 데이터 모델
	- → 객체 지향 데이터 모델 → 객체 관계 데이터 모델
	- → NoSQL 데이터 모델

### 3.3. 언어
- 데이터베이스 언어와 SQL(Structured Query Language)

- ① 데이터 정의어(DDL, data definition language)
	- 데이터베이스 스키마를 정의·수정·삭제한다.
	
	- CREATE, ALTER, DROP, TRUNCATE

- ② 데이터 조작어(DML, data manipulation language)
	- 데이터를 조작(삽입·검색·수정·삭제)한다.
	- 절차적 언어(procedural language): 어떤 데이터가 필요하고, 어떻게 찾을 것인지
	- 비절차적 언어(non-procedural language): 어떤 데이터가 필요한지 (SQL 등)
	
	- INSERT … INTO, UPDATE … SET, DELETE … FROM
	- 데이터 질의어(DQL): SELECT … FROM

- ③ 데이터 제어어(DCL, data control language)
	- 무결성, 동시성 제어, 보안, 회복 등에 필요한 규칙이나 기법을 정의한다.
	
	- 사용자 권한: GRANT … TO, REVOKE … FROM
	- 트랜잭션 제어어(TCL): COMMIT, ROLLBACK

## 4. 사용자
- 데이터베이스 관리자(DBA, database administrator)
	- 데이터베이스 시스템을 운영하고 관리한다.
	- 데이터베이스 설계, 구현, 유지보수의 전 과정을 담당한다.

- 오퍼레이터(operator)
	- DBMS가 운영되고 있는 컴퓨터 시스템과 전산실을 관리한다.

- 데이터베이스 설계자(database designer)
	- ERWin 등의 CASE(Computer-Aided Software Engineering) 도구를 이용해서 데이터베이스 설계를 책임진다.

- 응용 프로그래머(application programmer)
	- 일반 사용자가 사용할 수 있도록 프로그램을 만든다.

- 최종 사용자(end user)
	- 데이터베이스에 접근하여 데이터를 조작(삽입·삭제·수정·검색)한다.
