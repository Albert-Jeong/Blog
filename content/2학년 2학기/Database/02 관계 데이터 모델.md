## 1. 관계 데이터 모델의 개념
### 1.0. 데이터 모델링
- *공학 - 복잡한 것의 단순화*

- 데이터 모델링 정의
	- 현실 세계에 존재하는 데이터를 컴퓨터 세계의 데이터베이스로 옮기는 변환 과정
	- 데이터베이스 설계의 핵심 과정
	- 개념적 데이터 모델링 -> 논리적 데이터 모델링

- 데이터 모델(data model) 구조
	- 데이터 구조(data structure)
		- 저장할 데이터 타입과 관계
		- 정적 특징
	- 연산(operation)
		- 표현된 값들을 처리하는 작업
		- 동적 특징
	- 제약조건(constraint)
		- 구조적 측면의 제약 사항
		- 데이터 무결성 유지 목적

### 1.1. 기본적인 용어
- 릴레이션(relation)
	- 하나의 개체에 관한 데이터를 2차원 테이블의 구조로 저장한 것
	- 파일 관리 시스템 관점에서 파일(file)에 대응

- **관계형 모델**
	- 데이터를 ==관계==(행과 열로 표현되는 ==2차원 테이블==)로 표현한 모델

- *릴레이션의 행* -> ==튜플(tuple)==, *파일 시스템의 record에 대응*
	- 각 행에서 정의된 모든 속성 값들의 집합
	- **널**(null, `^`): 튜플을 삽입할 시점에 알려지지 않은 속성의 값
	- ==카디날리티(cardinality): 관계의 튜플 수==

- *릴레이션의 열(column)* -> ==속성(attribute)==, *파일 시스템의 field에 대응*
	- 테이블에 속성을 대표하는 유일한 이름이 있다.
	- ==도메인==(domain): 한 속성에 나타날 수 있는 값들의 집합(pool)
	- ==관계의 차수(degree): 한 관계의 총 속성의 수==

### 1.2. 스키마와 인스턴스
- ==관계 스키마, 내포==
	- 관계의 구조(이름, 속성들의 목록)를 정의하는 것

- **관계 인스턴스**, **외연**
	- 어느 시점에 관계 스키마에 들어있는 튜플들의 집합 (실제 데이터 값)
	- **무결성 제약조건**: 존재할 수 없는 인스턴스들이 저장되는 것을 제한

## 2. 릴레이션
### 2.1. 릴레이션의 특성
- **튜플의 유일성**
	- 동일한 튜플이 두 개 이상 존재하지 않음
	- 각 튜플을 고유하게 식별할 수 있는 (적어도 한 개 이상의) 속성의 집합(키) 존재

- **튜플의 무순서성**
	- 튜플의 순서는 무의미함

- **속성의 원자성**
	- 한 튜플의 각 속성은 원잣값을 가지며, 정의한 도메인 값만 가질 수 있음

- **속성의 무순서성**
	- 속성의 순서는 무의미함

### 2.2. 키의 특성
- 키
	- *고유한 식별자*
	- 릴레이션에서 각 튜플을 유일하게 식별할 수 있는 하나 이상의 속성들의 집합

- **유일성**(uniqueness)
	- 하나의 키 값으로 각 튜플을 유일하고 식별할 수 있어야 함

- **최소성**(minimality)
	- 각 튜플을 유일하게 식별할 수 키는 꼭 필요한 속성으로만 구성되어야 함
	- 만약 하나의 속성을 제거하면 식별할 수 없음

### 2.3. 릴레이션의 키
- **슈퍼 키**(super key)
	- 유일성 O: 한 릴레이션 내의 특정 튜플을 고유하게 식별하는 하나의 속성 또는 속성들의 집합
	- 최소성 X: 튜플들을 고유하게 식별하는 데 꼭 필요하지 않은 속성들을 포함할 수 있음
	
	- **후보 키**(candidate key)
		- 최소성을 만족하는 슈퍼 키
		- **복합 키**(composite key): 두 개 이상의 속성으로 이루어진 경우
		
		- **기본 키**(primary key)
			- 후보 키 중 선정한 키
			- **대리 키**(surrogate key): 자연스러운 기본 키를 찾을 수 없는 경우에 레코드 번호와 같이 인위적인 키 속성을 릴레이션에 추가한 것
		
		- **대체 키**(alternate key)
			- 기본 키가 아닌 후보 키

- **외래 키**(foreign key)
	- 어떤 릴레이션의 기본 키를 참조하는 속성
	- 관계 데이터베이스에서 릴레이션들 간의 관계를 나타내기 위해서 사용됨

- **외래 키의 유형**
	- 기본 키의 구성요소가 되는 외래 키
	- 자체 릴레이션의 기본 키를 참조하는 외래 키
	- ==다른 릴레이션의 기본 키를 참조하는 외래 키== (가장 많이 쓰임)

## 4. 무결성 제약조건
- **데이터 무결성**(data integrity)
	- (데이터베이스가 갱신될 때) 데이터의 정확성 또는 유효성을 의미함

- DBMS는 각각의 갱신 연산(삽입, 수정, 삭제)에 대하여 데이터베이스가 무결성 제약조건들을 만족하 도록 필요한 조치를 취함

### 4.1. 도메인 무결성 제약조건
- 도메인 무결성 제약조건
	- 원잣값 및 도메인에 지정된 값을 가진다.

### 4.2. 엔터티 무결성 제약조건
- 엔터티 무결성 제약조건
	- 기본 키는 널값을 가질 수 없다. (대체 키는 제외)

### 4.3. 참조 무결성 제약조건
- 참조 무결성 제약조건
	- 외래 키 값은 참조되는 릴레이션의 기본 키 값 중 하나거나 없으면 널값이어야 한다.

- 문제 여지
	- 참조하는 릴레이션에 / 튜플 **삽입** 시
	- 참조되는 릴레이션에 / 튜플 **삭제** 시
	- **수정**은 삽입과 삭제와 유사

- DBMS는 제한(restricted), 연쇄(cascade), 널값/디폴트값을 제공함
