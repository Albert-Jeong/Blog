## 1. 성능의 정의 (Defining Performance)
- **성능의 기준**
	- 비행기의 예시처럼, 성능은 속도, 수용량, 운항 거리 등 무엇을 기준으로 하느냐에 따라 달라진다.

- **두 가지 주요 척도**
	- **응답 시간**(Response Time/Execution Time): 하나의 작업을 완료하는 데 걸리는 시간 (개인용 컴퓨터에서 중요)
	- **처리량**(Throughput/Bandwidth): 단위 시간당 처리하는 총 작업량 (서버/데이터센터에서 중요)
	- *참고: 이 챕터에서는 주로 **응답 시간**에 초점을 맞춘다.*

### 예제. 처리량과 응답시간 (56)
- 다음과 같이 변경을 하면 컴퓨터 시스템의 처리량을 증대시키는가, 응답시간을 단축시키는가? 아니면 양쪽 모두인가?
	1. 컴퓨터의 프로세서를 더 빠른 버전으로 바꾼다.
	2. 여러 개의 프로세서가 각기 다른 태스크―예를 들면 웹 탐색 같은―를 담당하는 시스템에 프로세서를 하나 추가한다.
	- *대부분의 실제 컴퓨터에서 실행시간이나 처리량 중 하나가 변하면 다른 쪽에도 영향을 미치게 된다.*

## 2. 상대적 성능과 실행 시간 측정
- **상대적 성능**(Relative Performance)
	- 성능은 실행 시간의 역수이다. ($Performance = 1 / Execution Time$)
	- "X가 Y보다 n배 빠르다"는 식: $\frac{\text{Performance}_X}{\text{Performance}_Y} = \frac{\text{Execution Time}_Y}{\text{Execution Time}_X} = n$

- **시간 측정 방식**
	- **Elapsed time**(경과 시간)
		- I/O, OS 오버헤드, 유휴 시간 등을 모두 포함한 전체 시간
		- 시스템 성능을 나타냄
	- **CPU time**
		- 특정 작업을 처리하는 데 CPU가 소비한 시간(I/O 제외)
		- **사용자 CPU 시간**과 **시스템 CPU 시간**으로 나뉨

### 예제. 상대 성능 (57)
- 같은 프로그램이 컴퓨터 A에서 10초, B에서는 15초 걸린다면 A는 B보다 얼마나 빠른가?
	- $$\frac{P_A}{P_B}=\frac{ET_B}{ET_A}=\frac{15}{10}=1.5$$
	- A가 B보다 1.5배 빠르다.

## 3. CPU 성능 수식 (The CPU Performance Equation)
> 이 부분은 컴퓨터 구조에서 가장 핵심적인 공식들을 다룬다.

- **CPU 클러킹**(Clocking)
	- **Clock Period**: 한 사이클의 길이 (예: 250ps)
	- **Clock Frequency**(Rate): 초당 사이클 수 (예: 4.0GHz)

- **기본 공식**
	- $CPU Time = CPU Clock Cycles \times Clock Cycle Time = \frac{CPU Clock Cycles}{Clock Rate}$

- **명령어 수와 CPI**
	- **Instruction Count**(IC): 프로그램이 실행한 명령어의 총 개수 (컴파일러와 ISA에 의해 결정)
	- **CPI**(Cycles Per Instruction): 명령어 하나를 실행하는 데 걸리는 평균 사이클 수 (하드웨어 구조에 의해 결정)

- **최종 성능 공식**(The Big Picture)
	- $CPU Time = Instruction Count \times CPI \times Clock Cycle Time$
	- **알고리즘**: IC와 CPI에 영향
	- **프로그래밍 언어**: IC와 CPI에 영향
	- **컴파일러**: IC와 CPI에 영향
	- **ISA**(명령어 집합 구조): IC, CPI, 클럭 속도($T_c$) 모두에 영향

### 예제. 성능 개선 (61)
- 2GHz 클럭의 컴퓨터 A에서 10초에 실행되는 프로그램이 있다. 이 프로그램을 6초 동안에 실행할 컴퓨터 B를 설계하고자 한다. 클럭 속도는 얼마든지 빠르게 만들 수 있는데, 이렇게 하면 CPU 다른 부분의 설계에 영향을 미쳐 같은 프로그램에 대해 A보다 1.2배 많은 클럭 사이클이 필요하게 된다고 한다. 컴퓨터 B의 클럭 속도는 얼마로 해야 하겠는가?

| 컴퓨터 | 실행 시간 | 클럭 사이클 수 | 클럭 속도  |
| :-: | :---: | :------: | :----: |
|  A  |  10   |  1.0$C$  |  2GHz  |
|  B  |   6   |  1.2$C$  | $x$GHz |
- 실행시간비로 미지수 구하기
$$\frac{ET_A}{ET_B}
=\frac{10\text{ sec}}{6\text{ sec}}
=\frac{\frac{1.0C}{2\text{ GHz}}}{\frac{1.2C}{x\text{ GHz}}}
=\frac{5×x}{6×2}→x=4$$

### 예제. 성능식의 이용 (62)
- 같은 명령어 집합 구조를 구현한 컴퓨터 두 종류가 있다. 컴퓨터 A의 클럭 사이클 시간은 250 ps이고 어떤 프로그램에 대한 CPI는 2.0이며, 컴퓨터 B의 클럭 사이클 시간은 500 ps, CPI는 1.2이다. 이 프로그램에 관해서는 어떤 컴퓨터가 얼마나 더 빠른가?

| 컴퓨터 | 명령어 수 | 클럭 사이클 시간 | CPI |
| :-: | :---: | :-------: | :-: |
|  A  |  $I$  |   250ps   | 2.0 |
|  B  |  $I$  |   500ps   | 1.2 |

- ==CPU 성능==
	- 실행시간비 $$\frac{\text{ET}_A}{\text{ET}_B}
=\frac{I×2.0×250}{I×1.2×500}
=\frac{500}{600}$$
	- CPU 성능은 실행시간비의 역수이다. $$\frac{P_A}{P_B}=1.2$$
	- A가 B에 비해 1.2배의 속도이다.

### 예제. 코드의 비교 (63)
- 컴파일러 설계자가 같은 컴퓨터를 위해 생성된 두 가지 코드 1과 2 중 하나를 선택하려 한다. 하드웨어 설계자가 제공한 사실은 다음과 같다. 컴파일러 작성자가 어떤 상위 수준 언어 문장을 다음과 같은 두 가지 코드로 변환하는 방법을 고려하고 있다.
	- 어떤 코드가 더 많은 명령어를 실행하는가?
		- 코드 1 = 5 명령어, 코드 2 = 6 명령어
	- 어느 것이 더 빠른가?
		- 코드 2가 9 사이클로 더 빠르다.
	- 각 코드의 CPI는 얼마인가?
		- $CPI_1=10/5$, $CPI_2=9/6$

|     구분     | 명령어 A | 명령어 B | 명령어 C |
| :--------: | :---: | :---: | :---: |
|    CPI     |   1   |   2   |   3   |
| 코드 1 명령어 수 |   2   |   1   |   2   |
| 코드 2 명령어 수 |   4   |   1   |   1   |

## 4. 전력 트렌드와 한계 (Power Trends & The Power Wall)
- **전력 공식**(CMOS)
	- $Power \propto Capacitive Load \times Voltage^2 \times Frequency$
- **The Power Wall**(전력 장벽)
	- 과거에는 전압을 5V에서 1V로 낮추며 클럭 속도를 높일 수 있었다.
	- 하지만 더 이상 전압을 낮추기 어렵고 열을 식히는 데 한계가 있어, 단일 프로세서의 클럭 속도를 높이는 방식은 멈췄다.

### 예제. 상대 전력 (68)
- 복잡한 구형 프로세서와 비교하여 용량성 부하가 85%밖에 되지 않는 간단한 신형 프로세서를 개발하였다고 가정하자. 또한 신형 프로세서에는 가변 전압 기능이 있어서 구형에 비하여 전압을 15% 줄일 수 있었고 따라서 주파수도 15% 낮추었다면 동전력에는 어떤 영향을 미쳤겠는가?

| 프로세서 | 용량성 부하 |  전압  | 주파수<br>(frequency) |
| :--: | :----: | :--: | :----------------: |
|  구형  |  100%  | 100% |        100%        |
|  신형  |  85%   | 85%  |        85%         |
$$\frac{P_{new}}{P_{old}}
=\frac{0.85×0.85^2×0.85}{1×1^2×1}≈0.52$$
신형은 구형의 52%만큼 전력 소비

## 5. 멀티코어와 병렬 처리 (Multiprocessors)
- **단일 프로세서 성능의 정체**
	- 전력, 명령어 수준 병렬성(ILP)의 한계, 메모리 지연시간 등으로 인해 2000년대 중반부터 성능 향상이 둔화되었다.

- **멀티코어**(Multicore)
	- 칩 하나에 여러 프로세서를 탑재하는 방식으로 전환

- **과제**
	- 하드웨어가 알아서 처리해주던 ILP와 달리, 멀티코어는 프로그래머가 **명시적으로 병렬 프로그래밍**을 해야 한다. (로드 밸런싱, 통신, 동기화 문제 해결 필요)

## 7. 성능 관련 오해와 함정 (Fallacies and Pitfalls)
- 함정: **암달의 법칙**(Amdahl's Law)
	- 컴퓨터의 일부분만 개선해서는 전체 성능을 비례적으로 향상시킬 수 없다.
	- 개선되지 않은 부분(The common case)이 병목이 된다.
	- *교훈: 자주 발생하는 케이스를 빠르게 만들어라 (Make the common case fast).*

- 오류: **낮은 로드에서의 전력 소모**(Low Power at Idle)
	- 서버는 대부분 10~50% 로드 구간에서 작동하지만, 이때 전력 소모는 100% 로드일 때의 절반 수준으로 여전히 높다. (비효율적임)
	- 전력이 로드에 비례하도록 설계해야 한다.

- 함정: **MIPS**(Millions of Instructions Per Second)
	- MIPS는 단순히 초당 명령어 실행 수만 나타내므로, 명령어마다 하는 일의 양(복잡도)이 다른 서로 다른 ISA 간의 비교에는 부적절하다.

### 스스로 점검하기 (81)
|  측정값  | 컴퓨터 A | 컴퓨터 B |
| :---: | :---: | :---: |
| 명령어 수 | 100억  |  80억  |
| 클럭 속도 | 4GHz  | 4GHz  |
|  CPI  |  1.0  |  1.1  |

- **a. 어느 컴퓨터가 더 높은 MIPS 값을 갖는가?**
(million instructions per second)
$$\frac{\text{MIPS}_A}{\text{MIPS}_B}
=\frac{\frac{4}{1.0}}{\frac{4}{1.1}}=1.1$$
A가 B보다 1.1배 높다.

- **b. 어느 컴퓨터가 실제로 더 빠른가?**
$$\frac{ET_A}{ET_B}
=\frac{100/(MIPS_A×10^6)}{80/(MIPS_B×10^6)}
=\frac{5×1.0}{4×1.1}=\frac{2.5}{2.2}≈1.13$$
A가 B보다 1.13배 느리다.

## 8. 결론 (Concluding Remarks)
- 컴퓨터의 가격/성능은 기술 발전 덕분에 계속 향상되고 있다.
- 하드웨어와 소프트웨어 모두 **계층적 추상화**(Abstraction)가 핵심이다.
- **ISA**는 하드웨어와 소프트웨어의 인터페이스 역할을 한다.
- 최고의 성능 척도는 실**행 시간**(Execution Time)이다.
- **전력**(Power)이 성능 향상의 주요 제한 요소이며, 이를 극복하기 위해 **병렬 처리**(Parallelism)가 필수적이다.
